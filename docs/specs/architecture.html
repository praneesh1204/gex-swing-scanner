gexscan v2.2: tech universe, local web app, strategy visualizer

The visual companion to v2.2-visualizer-spec.md. Rev 2 replaces the static-site plan with a local web app: gexscan web runs a small server on 127.0.0.1 that serves the pages and a read-only JSON API, so the theme → ticker → scan flow and the Strategy Builder can load data on demand. This page shows the architecture, the request flow, the site map, wireframes of each page, the visualizer, the simulation, the moon-silver look and the phases. Every chart is drawn from a synthetic DEMO trade (spot $100, a 105/115 call spread) with real Black-Scholes and Monte Carlo numbers.

Read-only by design. gexscan never places orders: it never places, submits, modifies or cancels an order, in any broker, live or paper. The server answers GET and HEAD only, on 127.0.0.1. There are no forms, no order buttons and no broker links. All numbers are estimates, not financial advice, computed from delayed data. Every example on this page is a synthetic DEMO.

1 · System architecture

Top row, left to right: read-only sources, the data layer, analytics, the strategy engine and the local web server. Bottom row: your browser, which talks only to that server (same origin) and re-prices locally. Python stays the source of truth; engine.js is checked against it with shared golden vectors.

Server CSP on every response (W2): default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; form-action 'none'; base-uri 'none'; frame-ancestors 'none', plus X-Content-Type-Options: nosniff, Referrer-Policy: no-referrer and Cache-Control: no-store on the API. No static site is built: the pages are served by the local server, and every number arrives as JSON with its as_of.

2 · Request flow: from a click to an interactive page

Row 1 is the server: every page asks for JSON with a GET, and Python does the heavy, tested work. Row 2 is the browser: it checks its own pricing, draws the page, and re-prices locally while you drag a slider. Simulation is the only thing that goes back to the server, and only when you open it.

6 · Monte Carlo simulation with the exit plan

Runs in Python (analytics/simulate.py), seeded, only when you open Over time or Simulation. The same paths are scored twice: once following the idea's exit plan, once held to expiry, so the value of the exit rules is visible. Checks run on each daily close, in this order.

Labels shown on every simulated number: "Simulated from implied volatility. Real paths jump, skew moves and gaps happen." and "Daily closes only: intraday stop touches are not seen."

7 · The four metrics

MetricFormulaReads as
Contract valueV(S,t) = Σ sᵢ·qᵢ·100·Pᵢ(S,t,σᵢ·m)What the position is worth. Signed: the tooltip says "value to sell" or "cost to close".
P/L $V − EDollars made or lost if closed at mid at that price and date, all contracts.
P/L %(V − E) ÷ |E|Relative to the premium. Credit: +50 % = the usual profit target. Debit: −100 % = the debit is gone.
% of max risk(V − E) ÷ |MaxLoss|−100 % = max loss. Comparable across structures. Undefined risk shows UNDEFINED.
GreeksΔ, Γ, Θ/day, vega per vol pointFor the whole position, at the cursor price and date. Small multiples, one axis each.

E = Σ sᵢ·qᵢ·100·fillᵢ (positive for a debit, negative for a credit). sᵢ = +1 long, −1 short. m = the IV multiplier. Pᵢ is the BSM value with q; shares count with P = S. At expiry Pᵢ is intrinsic. Max profit, max loss and breakevens come from a dense expiry grid (2,001 points).

Colour-blind safe toggle: the profit arm turns blue

Validator (spec §6.9): each arm is monotone in lightness, adjacent ΔL ≥ 0.06, a single hue, and its light end is ≥ 5:1 against the tray: PASS. The arms match in OKLab L within 0.003 at every step. Series 1–3 on the card: PASS.
Green against red fails colour-blind separation (deutan ΔE 1.8): FAIL, as expected for that pair. Mitigations: every tile prints its signed value, loss tiles carry a faint 135° hatch, and the Colour-blind safe toggle swaps in the blue arm (red against blue, deutan ΔE 22.4: PASS).
Rules. Ramps are interpolated in OKLab and each arm is normalized to its own extreme (max loss, max profit). Tile text is dark (#101316) when the tile's L > 0.65, otherwise white. Text uses the ink tokens, never series colours. One axis per chart.
